## 1. Overview & Invocation Point

The **GitHub PR Feedback Reporter** is responsible for publishing deterministic, idempotent audit summary comments on target GitHub Pull Requests following the successful execution and database persistence of an audit run.

### Pipeline Execution Order

$$\begin{aligned}
\text{GitHub Webhook} &\longrightarrow \text{DB Audit Record (pending)} \\
&\longrightarrow \text{PR Source Acquisition (GitWorkspaceProvider)} \\
&\longrightarrow \text{Config A Static Analysis (Ruff + Semgrep CE)} \\
&\longrightarrow \text{DB Findings & Audit Status Finalized \& Committed} \\
&\longrightarrow \mathbf{GitHubPRFeedbackReporter.publish\_audit\_feedback()}
\end{aligned}$$

**Key Architectural Guarantees:**
- **Post-Commit Invocation**: The reporter is invoked **only after** static analysis has completed, findings are persisted, and the audit status transaction has been successfully committed to the database.
- **Fault-Isolated Execution**: A network timeout, GitHub rate-limiting, 401/403 permission error, or failure to post a comment **never** mutates a successful static audit into a failed audit. The audit status in the database remains `completed`. Reporting status is tracked independently in `audit.provenance["feedback"]`.
- **Zero Long-Lived DB Locks**: Database sessions are not held open across long-running GitHub HTTP requests.

## 2. Configuration & Authentication

### 2.1. Safe Enablement Defaults
Feedback publishing is governed by explicit opt-in configuration:

| Configuration Key | Type | Default | Description |
| :--- | :--- | :--- | :--- |
| `GITHUB_FEEDBACK_ENABLED` | bool | `False` | Must be explicitly set to `"true"` or `"1"` to enable outgoing comments. When disabled, the reporter immediately exits with status `disabled` without making network calls. |
| `GITHUB_TOKEN` | string | `None` | Personal Access Token (PAT) or GitHub App installation token. Must never be committed, logged, or included in URLs/reports. |

### 2.2. Required Permissions
When enabled, `GITHUB_TOKEN` requires the following GitHub REST API permissions on the target repository:
- `pull-requests: read` (to inspect existing comments and metadata).
- `pull-requests: write` or `issues: write` (to post and edit issue/PR comments via `/repos/{owner}/{repo}/issues/{issue_number}/comments`).

## 3. Idempotency & Duplicate Prevention

To prevent duplicate comments upon webhook redelivery or processor retries:

### 3.1. Stable Marker Embedding
Every comment generated by the reporter begins with a unique HTML marker comment:
```html
<!-- AI_CODE_AUDITOR_REPORT:<audit_id> -->
```
This marker is invisible in GitHub's rendered Markdown UI but machine-detectable by the reporter.

### 3.2. Deduplication Flow
1. **Local Provenance Check**: The reporter first checks if `audit.provenance["feedback"]["comment_id"]` is already known.
2. **Remote PR Comment Scan**: If not known locally, the reporter queries `GET /repos/{owner}/{repo}/issues/{pr_number}/comments` and searches for the exact marker `<!-- AI_CODE_AUDITOR_REPORT:<audit_id> -->`.
3. **Patch vs. Post**:
   - If a matching comment exists: The reporter sends `PATCH /repos/{owner}/{repo}/issues/comments/{comment_id}` to update the existing comment in-place.
   - If no matching comment exists: The reporter sends `POST /repos/{owner}/{repo}/issues/{pr_number}/comments` to create a single new comment.
4. **Crash Recovery Guarantee**: If GitHub creates a comment but the local application crashes before persisting the ID, subsequent retries will discover the existing comment via the embedded marker and update it rather than posting a duplicate.

## 4. Report Format & Truncation Policy

### 4.1. Report Structure
1. **Embedded Marker**: `<!-- AI_CODE_AUDITOR_REPORT:<audit_id> -->`
2. **Header & Coordinates**: Audit ID, configuration mode, overall status, execution duration, head commit SHA, and base commit SHA.
3. **Severity Counts Table**: Total findings broken down into High, Medium, Low, and Informational counts.
4. **Detailed Findings Table**:
   - Severity badge (`🔴 High`, `🟡 Medium`, `🔵 Low`).
   - Rule ID and Primary CWE (e.g. `S605 (CWE-78)`).
   - Normalized File location and line number (`path:line`).
   - Escaped finding description (Markdown table delimiters `|` escaped to `\|`, newlines formatted to single line or `<br>`).
5. **PR Scope Notice**: Explicit disclosure that findings are reported on changed files and may include pre-existing issues on unmodified lines within those files.

### 4.2. Truncation Policy
- Standard GitHub issue comments have a character limit (65,536 characters).
- To maintain readability and prevent API payload rejections, the findings table renders at most `max_findings` (default: 50).
- When total findings exceed 50, an explicit notification is displayed:
  `*Note: Showing first 50 of <N> findings. Full results are recorded in the persistent audit database.*`

## 5. Security & Secret Redaction

- **No Credential Leakage**: `_sanitize_reporter_error()` aggressively scrubs:
  - Exact `self.token` and `os.environ["GITHUB_TOKEN"]` strings.
  - Standard GitHub token formats: `ghp_[a-zA-Z0-9_]+`, `github_pat_[a-zA-Z0-9_]+`, `gho_[a-zA-Z0-9_]+`.
  - HTTP `Authorization: Bearer <token>` and `Basic <creds>` headers.
  - Embedded URL credentials (`https://user:pass@github.com`).
- **SSRF / Host Validation**: Repository full names are validated with `validate_repository(..., allow_local_repos=False)`. Dangerous characters, path traversal, and non-GitHub hosts are rejected before HTTP requests are dispatched.

## 6. Current Limitations & Verification Status

1. **Summary Comment vs. Inline Reviews**:
   - Current implementation publishes a **high-level PR summary comment** (via GitHub Issue Comments API).
   - It does **not** yet publish line-level inline review comments (which require diff hunk position mapping) or GitHub Checks API runs (which require a GitHub App).
2. **Live Verification Status**:
   - **Offline Verification**: **100% Verified** across 18 isolated test cases with mock HTTP transport (`httpx.MockTransport`), covering creation, updating, truncation, SSRF rejection, missing token, permission 403, rate-limit 429, and crash recovery.
   - **Live GitHub Verification**: **Not Executed** because `GITHUB_FEEDBACK_ENABLED` is `False` by default and no authorized live test PR was designated for unsolicited comment publishing.
