5. **Final Decision 5 — Finding ↔ Ground-Truth Matching (Locked Evaluation Rule)**:
   - A predicted finding is a True Positive (TP) if and only if ALL three conditions hold:
     - *File match*: normalized predicted file path exactly matches normalized ground-truth file path (path-prefix differences removed during normalization).
     - *Category / CWE match*: predicted category/CWE matches ground-truth category/CWE, OR matches an explicitly pre-declared acceptable alternative CWE associated with that ground-truth case. (Alternative CWE sets must be defined prior to evaluation; no post-hoc mappings).
     - *Location match*: predicted line range overlaps the ground-truth line range, OR falls within the locked tolerance window around the ground-truth range.
   - *Locked Tolerance Window*: Set to exactly **±10 lines** applied uniformly across Configurations A–D (±5 lines is removed as an unresolved alternative).
   - *Locked Edge-Case Rules*: Multi-line findings satisfy location via any line overlap. One-to-one matching: each ground-truth defect is consumed by at most one matching prediction. Additional unmatched predictions on buggy PRs = False Positive (FP), even if another prediction from the same PR already matched that defect. Any finding on a clean PR = False Positive (FP). A ground-truth defect with no prediction satisfying all three conditions = False Negative (FN).
   - *Diagnostic Metrics*: Exact line-match rate, line distance, and category-only match rate remain optional diagnostics that do NOT alter primary TP/FP/FN counts.
6. **Final Decision 6 — Evaluation Metric Targets (Precision / Recall)**:
   - Precision $\ge 75\%$ and Recall $\ge 60\%$ are research targets / empirical hypotheses, NOT hard acceptance criteria or pass/fail gates. No thesis-success gate. Results will be evaluated and interpreted empirically across Configurations A–D.
7. **Final Decision 7 — Implementation Stack Scope**:
   - Supervisor-confirmed high-level scope: PR-based auditing, existing LLM API orchestration/integration (no model training/fine-tuning), 3 core contribution pillars (Hybrid Audit, Repo-level Context, Quantitative Evaluation), Core MVP on Git PR vs. AI Guardrail as Advanced/Stretch.
   - Current implementation stack: Python, FastAPI/Flask, GitHub Actions, PostgreSQL/pgvector remain the validated student technical selections for building the system.

## Known Pitfalls / Rules Learned the Hard Way
- Don't let a research agent decide scope, bug categories, or CWE mappings — it gathers evidence; the student + supervisor decide.
- Don't accept a forced CWE mapping just because a plausible-looking entry exists — leave it unmapped if it doesn't truly fit.
- Don't treat AI/agent-generated bug cases as ground truth without an auditable chain (commit -> defect -> test -> fix -> verification) or supervisor sign-off.
- Don't invent Ruff/Semgrep/LLM performance numbers — report only experimentally measured ones.
- Keep research tooling (GPT Researcher, Spec Kit, SWE-smith, SWE-Forge) OUT of the production system architecture — it's thesis-development tooling only.
- **GPT Researcher is a candidate-discovery and research-assistance tool, not a ground-truth authority.** It may search repositories, locate candidate issues/PRs, collect links, and propose candidate categories/CWEs. It must NEVER declare a case valid, establish ground truth, invent reproducers or line ranges, or infer defect existence merely because code looks plausible. Acceptance requires verification against Tier 1 primary sources.
- **RealVuln is a contemporary literature reference, not an authoritative standard.** It is an academic preprint (arXiv:2604.13764, April 2026) associated with Kolega Labs whose own commercial scanner is benchmarked. It provides a relevant example of proximity-based matching, but does not "prove" our matching rules.
- **GPT Researcher citation metadata must be treated as unverified by default.** GPT Researcher may correctly identify relevant research topics while producing incorrect authors, arXiv IDs, URLs, dates, venues, repository links, or quantitative claims. Every substantive citation used in thesis research must be independently checked against the original authoritative source before being treated as verified evidence. Do not rely on topic-level plausibility or GPT Researcher's bibliography alone. Remember: **Research execution ≠ citation verification.** The successful completion of a GPT Researcher run does not make its references academically verified.
